# 飞行棋 · 局域网联机版（主机权威）

把原来的**单机飞行棋**变成 **4 人局域网联机**：1 鬼 + 3 人，各用自己设备。

**架构：主机权威（host-authoritative）**
- **游戏逻辑完全跑在"主机玩家"的浏览器里**（沿用你原来的单机代码，规则一字未改）；
- 服务器只做**中转**：收集大厅、分配座位、转发"状态快照"和"操作"；
- 其他玩家用快照同步画面；轮到自己时，把操作转发给主机执行。

> 为什么这样做：你原来的游戏逻辑很完整（52 格环形棋盘 + 4 条专属道 + 抓人/破译/撤离 + 5 角色技能），
> 完整"服务器权威"改写风险大。主机权威**逻辑零改动**，能最快把真游戏联起来。

## 运行（局域网）

**在主机电脑上：**
```bash
cd fxq-hostonline
npm install        # 第一次
npm start
```

**查内网 IP：** 另开窗口 `ipconfig`，找 `192.168.x.x`。

**大家访问：**
- 主机自己：`http://localhost:3000`
- 其他人：`http://192.168.x.x:3000`

> 手机连**同一个 WiFi**；若连不上，多半是**防火墙**——用管理员 PowerShell 执行：
> ```powershell
> netsh advfirewall firewall add rule name="fxq-3000" dir=in action=allow protocol=TCP localport=3000
> ```

## 怎么玩

1. 4 人各输名字、**同一房间号**进入大厅；
2. **第一个进房的人 = 主机**；
3. 每人选**阵营**（👻 鬼 / ✈ 人）和**角色**——必须**恰好 1 名鬼、3 名人**；
4. 主机点**开始游戏**；
5. 轮到你时，屏幕顶部提示「👉 轮到你行动」——你掷骰、点棋盘落点、用技能；
   不是你的回合，操作无效（主机也会拦截）。

---

## 联机层怎么工作（给以后维护看）

| 角色 | 做什么 |
|---|---|
| **主机** | 跑完整游戏；每 250ms 广播一次状态快照；收到观众操作后**校验座位**（只接受当前回合玩家）再执行 |
| **观众** | 用快照渲染棋盘；把 `doRoll / chooseDir / moveTarget 点击 / useSkill / endTurn …` 转发给主机 |
| **服务器** | 无游戏逻辑，纯转发 |

**关键点：**
- 快照里的 `g` 是完整游戏状态，`pieces` 是各棋子位置/状态；
- 观众端**直接复用游戏的渲染函数**（renderPieces / renderActions / updateUI…），所以画面和主机一致；
- 观众端的**全部输入函数被替换成"转发"**，棋盘落点点击用事件捕获拦截转发。

## 已知限制（当前是 M1）

- **主机必须一直开着浏览器**；主机退出 = 本局结束（服务器会提示）；
- 观众端**每 250ms 刷新一次**，动画走位不如单机顺滑（后续可做逐一格动画）；
- **"再来一局 / 重开"尚未联机同步**（只有本地）；
- 角色选择是**简化版**（下拉框），还没做单独的阵营界面；
- ⚠️ **浏览器端渲染逻辑未经自动化测试**（沙箱无浏览器）——中继通信层已测通，但请实机验证画面。
